00 · Контекст

О проекте и нише

RMA — агентство управления онлайн-репутацией (ORM), принадлежит Attolini Agency. Удаление негативного контента из Google, форумов и соцсетей, деиндексация прессы, право на забвение, управление отзывами (Trustpilot, Google Reviews), юридическое сопровождение. Основной рынок — Италия; интернациональный трафик — на английском.

Сейчас сайт — один длинный лендинг на двух языках (EN по умолчанию, IT). Ниша относится к чувствительной (репутация + юридические/деловые решения), близка к YMYL, поэтому Google предъявляет к ней повышенные требования по экспертности и доверию. Это нужно учитывать в каждом разделе ТЗ.

Важно для исполнителя

Не использовать любые «серые» приёмы (PBN, накрутка поведенческих, клоакинг, спам-ссылки). Для агентства, которое само торгует репутацией, чистота методов — часть продукта. Любая санкция = репутационный удар по клиенту.

Что фиксируем на старте (baseline)

02 · Фундамент

Техническая база

Блокер №1 — решить до всего остального

Контент рендерится на клиенте через Babel + React из CDN

Сейчас весь текст и разметка появляются только после загрузки и исполнения JavaScript (трансляция JSX в браузере). В исходном HTML, который получает поисковый робот, контента практически нет. Для коммерческого продвижения это недопустимо: индексация будет неполной и нестабильной, скорость — низкой.

Требуется: перевести проект на серверный рендеринг или пререндеринг — SSR/SSG (Next.js / Astro / Vite SSR) либо как минимум статический prerender каждой языковой версии, чтобы готовый HTML с текстом, заголовками и мета-тегами отдавался сразу, без выполнения JS. Babel-в-браузере из продакшена убрать полностью (собирать бандл заранее).

Базовый технический чек-лист

  • HTTPS на всём сайте, 301-редирект http → https и склейка зеркал (www/без-www — выбрать одно).
  • robots.txt с указанием на sitemap; закрыть служебное, не закрывать CSS/JS.
  • XML-sitemap со всеми каноническими URL и языковыми версиями; автообновление; submit в GSC.
  • Канонические теги (rel="canonical") на каждой странице; единый формат URL (нижний регистр, без лишних слешей и параметров).
  • Человеко-понятные ЧПУ: /it/rimozione-recensioni-google/, /en/remove-negative-content/.
  • Корректные коды ответа: 404 для несуществующего, 301 для переездов; никаких soft-404.
  • Доступная семантика: один <h1> на страницу, логичная иерархия H2/H3, alt у изображений, осмысленные anchor-тексты.
  • Лендинг и SEO-страницы должны открываться без JS (контент в HTML). Three.js-визуал — прогрессивное улучшение, не несущее текста.
Подсказка по реализации

Three.js-фон и интерактив оставляем как декоративный слой поверх статического HTML. Для робота и для отключённого JS должен оставаться полный текстовый контент. Любой важный текст НЕ должен рисоваться внутри canvas.

03 · Скорость

Core Web Vitals и производительность

После перехода на SSR/SSG довести полевые показатели до «зелёных» на мобайле — это и фактор ранжирования, и фактор конверсии.

МетрикаЦельЧто делать
LCP< 2.5 cКритический CSS инлайн, preload основного шрифта, оптимизация hero, отложенная инициализация Three.js.
INP< 200 мсМинимизировать JS на главном потоке; рендер canvas в requestAnimationFrame с паузой вне вьюпорта (уже реализовано — сохранить).
CLS< 0.1Резервировать размеры под медиа и canvas, font-display:swap, без сдвигов от поздней подгрузки.

Прочее

  • Изображения в WebP/AVIF, loading="lazy" для второго экрана и ниже, корректные width/height.
  • Шрифты: preconnect + font-display:swap, подключать только используемые начертания.
  • Three.js грузить отложенно (после first paint), гейтить на prefers-reduced-motion и на слабых устройствах давать статичный фон.
  • Кэширование статики, HTTP/2+, gzip/brotli, CDN для ассетов.

05 · Архитектура

Структура сайта

Текущий одностраничник не закрывает ядро: под каждый коммерческий кластер нужна посадочная. Предлагаемая структура (на каждый язык в своём каталоге /it/, /en/):

Коммерческие посадочные
  • Главная (хаб ORM)
  • Удаление отзывов Google / Trustpilot
  • Право на забвение / деиндексация
  • Удаление статей и прессы
  • Негативные подсказки Google
  • Юридическое сопровождение
Поддержка и доверие
  • О компании / команда (E-E-A-T)
  • Кейсы / результаты (анонимизированные)
  • Блог (информационные кластеры)
  • FAQ (под FAQPage-разметку)
  • Контакты + локальная страница (Milano)
  • Privacy / Cookie / правовые
  • Глубина вложенности — не более 3 кликов от главной; сквозная перелинковка хаб ↔ услуги ↔ блог.
  • Хлебные крошки с разметкой BreadcrumbList.
  • Контекстные внутренние ссылки из блога на коммерческие посадочные (с осмысленными анкорами).

07 · i18n

Многоязычность и hreflang

Сейчас язык переключается на клиенте через localStorage — для SEO это невидимо. Нужны отдельные индексируемые URL на каждый язык и корректный hreflang.

  • Языковые версии в каталогах: /it/... и /en/... (или поддомены — выбрать одну схему).
  • На каждой странице — взаимные hreflang + x-default:
<!-- на странице услуги -->
<link rel="alternate" hreflang="it" href="https://webreputation.agency/it/rimozione-recensioni/">
<link rel="alternate" hreflang="en" href="https://webreputation.agency/en/review-removal/">
<link rel="alternate" hreflang="x-default" href="https://webreputation.agency/en/review-removal/">
  • Контент реально переведён (не машинно «как есть»); метаданные тоже локализованы.
  • Переключатель языка — обычные <a href> на соответствующие URL, а не JS-замена текста.
  • Канониклы указывают на ту же языковую версию, не кросс-язычно.
08 · Schema.org

Структурированные данные

Разметка JSON-LD на релевантных страницах. Минимальный набор:

  • Organization (+ LocalBusiness для Milano): название, лого, адрес, контакты, sameAs на соцсети.
  • Service — на каждой посадочной услуги (тип услуги, область, провайдер).
  • FAQPage — на FAQ и блоках вопросов посадочных (шанс на rich-результат).
  • BreadcrumbList — на всех вложенных страницах.
  • Article — на статьях блога (автор, дата, издатель).
Осторожно с отзывами

Разметку Review / AggregateRating (звёзды 4.9 и т.п.) использовать только если рейтинг подтверждён реальными отзывами на сайте и соответствует правилам Google. Самоназначенные звёзды — риск ручной санкции. Внешний рейтинг (Trustpilot) размечать нельзя.

// пример Organization (фрагмент)
{
  "@context": "https://schema.org",
  "@type": "ProfessionalService",
  "name": "RMA — Reputation Management Agency",
  "url": "https://webreputation.agency/",
  "areaServed": ["IT", "EU"],
  "sameAs": ["https://..."]
}

После внедрения — валидация в Rich Results Test и мониторинг отчёта «Улучшения» в Search Console.

09 · Контент

Контент-стратегия

Под информационные кластеры — блог, который перехватывает аудиторию на ранней стадии («можно ли удалить отзыв», «сколько стоит», «законно ли») и ведёт на коммерческие посадочные.

Темы-опоры (IT, далее перевод на EN)

  • Как удалить ложный отзыв с Google: что реально, что нет.
  • Право на забвение в ЕС: как работает деиндексация на практике.
  • Сколько стоит удаление негатива и от чего зависит цена.
  • Что делать, если о компании вышла негативная статья.
  • Негативные подсказки Google: почему появляются и как убрать.

Формат — экспертные материалы с авторством, ответами под featured snippet и FAQ-блоком. Регулярность и приоритет тем — по потенциалу трафика и близости к деньгам. Периодически обновлять старые материалы (content refresh).

10 · Доверие

E-E-A-T и YMYL

Ниша затрагивает деловую репутацию и юридические вопросы — Google оценивает опыт, экспертность, авторитет и доверие особенно строго. Сигналы доверия — приоритет, не «по остаточному».

  • Страница «О компании» с реальной командой, опытом, юр-специализацией, годами на рынке.
  • Авторство статей с экспертными профилями (опыт в ORM/праве).
  • Анонимизированные кейсы и измеримые результаты; реальные отзывы клиентов.
  • Прозрачные контакты, юр-реквизиты, P.IVA, физический адрес, политика конфиденциальности и cookie (баннер согласия уже реализован).
  • Внешние упоминания бренда в авторитетных СМИ/каталогах (PR, не спам-ссылки).
  • Чёткое раскрытие методов и гарантий, без преувеличений и обещаний «100% за день».
11 · Local

Локальное SEO

  • Оформить и оптимизировать Google Business Profile (категория, услуги, описание, фото, регулярные посты).
  • Единые NAP (название, адрес, телефон) на сайте и во всех каталогах.

  • Локальная посадочная (Milano) при наличии офиса; сбор реальных отзывов в профиль.
12 · Links

Ссылочный профиль

Качество строго важнее количества — для репутационного агентства токсичный профиль недопустим.

  • Цифровой PR и экспертные комментарии в СМИ по теме репутации/права (естественные ссылки и упоминания).
  • Отраслевые каталоги, профильные ассоциации, гостевые экспертные публикации.
  • Разнообразие анкоров (бренд / безанкорные / по запросу) в естественной пропорции.
  • Регулярный аудит профиля, отклонение спамных доноров при необходимости.
  • Запрещено: покупка ссылок пачками, PBN, биржи низкого качества, спам-комментарии.
13 · Analytics

Аналитика и отслеживание

  • Google Search Console и GA4 на всех языковых версиях; связать между собой.
  • Цели/события: отправка формы аудита, клик по WhatsApp, клик по телефону/почте.
  • Учитывать согласие на cookie (баннер уже есть) — аналитику грузить по согласию (Consent Mode).
  • Отслеживание позиций по кластерам (Ahrefs/Semrush), отчёт по Core Web Vitals.
  • Ежемесячный дашборд: трафик, позиции, заявки, выполнено/план.
